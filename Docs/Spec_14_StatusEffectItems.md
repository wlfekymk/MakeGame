# #14 상태이상 치료 아이템 획득 경로 확정

## 목적
붕대/해독제/부목 SO와 레시피는 이미 존재한다(온보딩 때 "SO 없음"으로 오판했던 부분 — 아래
"SO 실물 확인으로 바뀐 판단" 참고). 실제 레시피 재료를 확인해, 상태이상 발생 시점부터
사망까지의 시간 안에 치료가 가능한지 검증한다.

## 실제 데이터 (asset 원문 확인)

| 결과 아이템 | 필요 재료 | 스킬 레벨 | 경험치 |
|---|---|---|---|
| 붕대 (`Recipe_붕대`) | 천조각 ×2 | Craftsmanship Lv1 | 5 |
| 해독제 (`Recipe_해독제`) | 코코넛 ×1 + 천조각 ×1 | Craftsmanship Lv1 | 5 |
| 부목 (`Recipe_부목`) | 대나무 ×2 + 노끈 ×1 | Craftsmanship Lv1 | 5 |
| (부목 선행) 노끈 (`Recipe_노끈`) | 야자잎 ×3 | Craftsmanship Lv1 | 6 |

천조각(`Item_천조각`)은 자체 레시피가 없는 **원재료**다. 설명: "찢어진 옷가지나 가방에서 얻는
천" — 채집 노드가 아니라 잔해 루팅 계열로 추정되나, 정확한 스폰 시스템(`IslandResourceSpawner`/
`ResourceNode` 설정)은 이번 확인 범위에 없어 단정할 수 없다.

## 시간 분석

- **출혈**: 1.2/초, 무보호 시(100체력 기준) **83초**에 사망. 단 곰(direct 10)/식인종(direct
  10)/상어(direct 18) 접촉 시 직접 피해가 동시에 들어가므로 실제 여유 시간은 더 짧다
  (예: 접촉 순간 체력 10~18 즉시 손실 후 남은 체력만큼만 출혈 여유).
- **중독**: 0.8/초, 125초에 사망 — 붕대보다 여유가 있다.
- **골절**: 체력 피해 없음(이동속도만 저하) — 즉사 위험 없음, 재료 준비 여유 충분.
- 붕대 제작 자체(재료를 들고 있는 상태에서 크래프팅 UI 조작)는 수 초 내로 처리될 것으로 보이나
  정확한 처리 시간은 `CraftingSystem.cs`가 이번 확인 범위 밖이라 확인하지 못했다.
  **[확인요청] systems-engineer: CraftingSystem.Craft 류 메서드가 즉시 처리인지, 별도 제작
  시간(딜레이)이 있는지 확인 필요.**
- 병목은 "재료를 이미 들고 있는가"다. 천조각을 사전에 확보해두지 않은 상태에서 최초로 출혈을
  입으면, 채집 노드 위치 확인 → 이동 → 상호작용 → 복귀 → 제작까지 83초(그마저도 direct
  damage로 더 짧아짐) 안에 끝내는 것은 **현실적으로 불가능에 가깝다**고 판단한다.

## 결정

**시작 인벤토리에 붕대 1개를 포함시킨다.**

### 근거
- 상태이상 중 출혈만이 "무기 없는 최초 조우 한 번"만으로 83초(그 이하) 내 사망 가능한
  유일한 케이스다. 중독(125초)과 골절(비치명)은 재료를 채집할 시간적 여유가 상대적으로 있다.
- 첫 위험요소 조우에서 사전 학습 없이 사망하는 것은 플레이어 경험상 불공정하다 — 이미
  `Campfire.cs` 주석에 "라이터를 시작 아이템으로 지급"하는 것과 동일한 완화 철학을 출혈에도
  적용한다.
- 해독제/부목은 시작 지급하지 않는다. 중독·골절은 첫 조우 이후 재료를 구할 시간적 여유가
  있다고 판단.

### 추가 조치 제안
- 붕대 레시피의 `requiredSkillLevel`은 이미 1(최저)이라 추가 완화 불필요.
- **[요청] systems-engineer**: 천조각이 잔해 루팅 전용이라면 초반 접근성이 너무 낮을 수 있다.
  일반 채집 노드(덤불/야자수 등)에도 천조각을 드랍 목록으로 추가할지 검토 요청.

## 수정 대상
- `PlayerInventory.startingItemPool`(Inspector 데이터, 씬/프리팹에 직렬화)에 `Item_붕대` 1개 추가.
  - 이 필드 자체는 game-designer 소유 데이터(SO 아이템 지정)이지만 실제 저장 위치가 씬/프리팹
    파일이라 직접 수정 권한이 애매하다.
  - **[확인요청] unity-operator**: `PlayerInventory` 인스턴스의 `startingItemPool`에 현재 무엇이
    들어있는지 Inspector에서 확인. `PlayerInventory.cs` 주석은 예시로 "고무보트, 생수, 라이터,
    칼 등"만 언급하고 붕대는 언급하지 않는다 — 실제 목록은 씬에만 있어 이번 범위에서 확인 불가.
  - 확인 후 목록에 `Item_붕대`가 없다면 systems-engineer/unity-operator가 추가.

## 수용 기준
1. 새 게임 시작 시 인벤토리에 붕대(`Item_붕대`) 1개가 포함된다.
2. 곰/식인종에게 최초 피격 후 도주하더라도, 그 자리에서 즉시 붕대를 사용해 출혈을 치료할 수
   있다(추가 재료 채집 불필요).
3. 해독제/부목은 여전히 제작으로만 획득 가능(정책 변경 없음).

## SO 실물 확인으로 바뀐 판단
온보딩 보고에서 "치료 아이템(붕대/해독제/부목)이 ItemData 에셋으로 존재하지 않아 출혈에 걸리면
치료 수단이 실질적으로 없다"고 결론 내렸던 부분은 **틀렸다.** 실제로는 세 아이템과 레시피가
모두 존재한다. 다만 이번 분석으로 새로 드러난 진짜 문제는 "아이템이 없다"가 아니라
**"재료(천조각)를 사전에 들고 있지 않으면 출혈 타이머 안에 만들 수 없다"**는 접근성 문제였다.

## 담당 제안
- 스펙 확정: game-designer (본 문서, 완료)
- startingItemPool 반영: systems-engineer / unity-operator
- 천조각 드랍처 확대 검토: systems-engineer
- CraftingSystem 처리 시간 확인: systems-engineer
