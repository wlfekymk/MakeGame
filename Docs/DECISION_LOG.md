# DECISION_LOG — 왜 그렇게 정했는가

**이 문서의 용도**: 컨텍스트가 압축·소멸해도 살아남아야 하는 **판단의 근거**를 담는다.

- **무엇을 했는가** → `git log`
- **어떻게 하는가** → `Docs/AGENT_BRIEF.md`
- **어떤 API가 있는가** → `Docs/API_REFERENCE.md`
- **왜 그렇게 정했는가 / 무엇을 시도했다 버렸는가** → **이 문서**

실측 결과 컨텍스트를 버릴 때 가장 비싸게 사라지는 것은 사실이 아니라 ①결정의 이유 ②시도했다
버린 것이다. 사실은 파일을 다시 읽으면 되지만, 버린 선택지는 기록이 없으면 **다음 담당이 그대로
다시 시도한다.** 새 결정을 내리면 여기에 한 줄 추가하라.

## A. 에이전트 운영 (2026-08-19 확정)

### A1. 중첩 에이전트를 전면 적용하지 않고 조건부로 제한했다
- **조건**: 800줄 초과 파일을 이해해야 하거나, 구조 파악에 큰 파일 3개 이상이 필요할 때만.
- **이유**: 절감 효과가 큰 파일에 몰려 있다(2,225줄 파일 하나 기준 약 15배). 작은 확인까지
  위임하면 지연만 늘고 절감은 미미하다.
- **재검토 조건**: 다음 대규모 작업에서 조각 간 인계 비용을 실측한 뒤.

### A2. 10~20턴 상한을 아직 규칙으로 박지 않았다
- **이유**: 조각 간 인계 비용을 실측하지 못했다. 그리고 **컨텍스트를 완벽히 버려도 이론 바닥이
  2.2배뿐**이다 — 고정 프리픽스(시스템 프롬프트 + 도구 스키마)가 재읽기의 45%라, 턴 수가
  그대로면 쪼개도 그만큼은 남는다.
- **따라서 우선순위**: 턴 수 줄이기(스크립트 우선) > 컨텍스트 줄이기(조각화).

### A3. 못 줄이는 하한이 있다
- 서브에이전트 첫 컨텍스트 25.1K 중 **24.4K가 시스템 프롬프트 + 도구 스키마**(내 지시문은 0.6K).
- 메인 대화는 71K. 압축을 아무리 잘해도 이 밑으로 못 내려간다.
- **시사점**: 지시문을 짧게 쓰는 것은 효과가 거의 없다. 턴을 줄여라.

### A4. 실측 근거 (2026-08-18 야간 작업 세션)
- 에이전트 202기, 총 16,657턴, 도구 호출 9,700회.
- 도구 결과 원본 7.2M 토큰 → 이후 턴에서 **502M으로 재처리(평균 70배)**.
- 재읽기 구성: 고정 프리픽스 45% / 누적 도구 결과 52% / 어시스턴트 출력 3%.
- 대표 에이전트(70턴): 최종 컨텍스트 159,911 토큰, 누적 재읽기 8,090,961 토큰 = **51배**.

## B. 오늘(0.2.47~0.2.51 야간) 의도적으로 하지 않은 것

**다시 제안하지 마라. 하려면 아래 이유를 먼저 반박하라.**

| 항목 | 왜 안 했나 |
|---|---|
| 키 리바인딩 | 입력 대기 모달 UI 필요 + `RuntimeInitializeOnLoadMethod`로 나중에 생기는 컴포넌트가 있어 "가끔 안 먹는" 구조가 생긴다 |
| 진짜 뗏목 전복 | Rigidbody 없이 트랜스폼 구동이라 뒤집히면 승선 판정·갑판 격자가 무효가 되고, 세이브에 자세가 없어 F9 한 번에 사라진다. 경고 + 속도 감소 + 적재물 유실로 대체 |
| 상자 안 음식 부패 | `ChestItemSaveEntry`에 나이 필드가 없다. 절반만 동작하는 상태를 만들지 않으려고 통째로 보류(= 상자는 냉장고) |
| 밭·훈연기를 `StructureType` enum에 추가 | enum 중간 삽입이 기존 세이브 정수를 밀 위험. 별도 목록(`smokers`/`farmPlots`)으로 저장. **나중에 정리 대상** |
| 던진 창·난파선 수거 상태 저장 | 기존 수거 지점(침몰 화물·진주조개·여객기)이 전부 미저장이다. 여기만 고치면 규칙이 두 벌로 갈린다 |
| 난이도를 환경 피해에 적용 | 굶주림·갈증은 이미 `HungerDrainMultiplier`로 난이도가 걸려 있다. 피해량까지 곱하면 같은 손잡이가 두 번 |
| 요리 스킬을 날음식에 적용 | 안 굽고 먹는 쪽이 스킬로 강해져 조리 루프가 무의미해진다 |
| `saveContentVersion` 올리기 | "복원 규칙이 바뀐 게 아니라 순수 추가"이면 올리지 않는다. 올리면 옛 세이브에 엉뚱한 안내 로그가 뜬다 |

## C0. 세이브 호환 규율 해제 (2026-08-19 디렉터 결정)

**"세이브 데이터는 언제든 날려도 된다."** 출시 전이고 플레이어가 디렉터 한 명이라, 옛 세이브를
지키려고 구조를 비틀던 비용이 이득보다 크다고 판단했다. 상세는 `AGENT_BRIEF.md` 3절 상자.

이 결정으로 **막혀 있던 정리들이 풀린다** — 다음에 손볼 때 같이 처리한다:
- `Smoker`/`FarmPlot`이 각자 들고 있는 별도 세이브 목록 → `StructureType` enum 하나로 통합
  (C3와 같은 뿌리다. 지금까지는 enum 재번호가 옛 세이브를 깨서 미뤘다.)
- `SaveData`의 죽은 필드·중복 필드 정리, 필드 이름을 뜻에 맞게 개명
- 세이브 마이그레이션 분기들을 **유지 말고 삭제**

**해제되지 않은 것 3개** (성격이 다르므로 계속 지킨다):
1. 옛 세이브를 읽다 예외가 나도 **게임이 죽으면 안 된다** — 조용히 새 게임으로 떨어질 것.
2. `.bak`/`.tmp` 복구 경로 유지 — 이건 "이번 판 저장이 끊겼을 때"용이지 옛 세이브 호환이 아니다.
3. rng 스트림 규율 — 세이브와 무관하게 같은 worldSeed가 같은 월드를 만들어야 버그가 재현된다.

**보고 의무**: 세이브 구조를 깨는 변경을 했으면 보고에 한 줄 남길 것(디렉터가 새 게임으로
시작해야 하는지 알아야 한다).

## C0-b. 공략집 동결 (2026-08-19 디렉터 지시)

**"공략집은 앞으로 더 이상 업데이트 하지 마."** `Docs/Manual/`은 **0.2.55 스냅샷으로 동결**한다.

- 게임을 바꾸는 작업의 후속 항목에 안내서 갱신을 **넣지 않는다.** 보고에도 "안내서도 고쳐야 한다"고
  적지 마라 — 이미 결정된 사항이다.
- 안내서의 수치는 시간이 지나면 틀린 값이 된다. **그게 의도다.** 최신 사실이 필요한 쪽은
  `Docs/AGENT_BRIEF.md`와 코드다.
- 0.2.55까지는 맵 재배치·특대 섬 조건 변경까지 반영된 상태로 맞다.
- 해제는 디렉터가 명시적으로 지시할 때만.

- **도구를 `/tmp`에만 두지 마라.** `gate.py`가 그 상태였다. `Tools/agent/gate.py`로 편입했다.
- **에이전트는 20만~24만 토큰에서 강제 종료된다**(API 오류로 나타난다). 두 번 당했고, 둘 다
  파일은 써졌는데 배선이 안 된 상태였다. **중단되면 먼저 상태를 확인하고 이어받아라.**
- **tar md5 대조는 양측 정렬을 맞춰라**(`sort`). 안 맞추면 내용이 같아도 해시가 다르다.
- **`device_bash`는 삭제를 못 한다.** `_to_delete/`로 옮겨라.
- **파일을 고치기 전에 `cat VERSION`부터 확인해라.** 2026-08-19에 클라우드 작업본이 하루에
  세 번 되돌아갔고, 한 번은 되돌아간 옛 파일 위에 수정을 얹었다가 알아채고 버렸다.
  버전이 예상과 다르면 **PC에서 전체를 다시 내려받고** 시작한다.
