# 30~90분 검산 — 쉼터가 열린 뒤 이 게임에 무슨 일이 일어나는가

`Design_FirstThirtyMinutes.md`의 후속. 표기 규약 동일 —
`[실측]` = 파일·줄 번호를 댄 값 · `[계산]` = 실측만으로 나온 산술 · `[추정]` = 내가 지어낸 값.

**한 줄 요약: 30~90분 구간에 새로 열리는 것은 0개다. 그리고 이 구간은 통째로 건너뛸 수 있다.**

## 0. 결론 먼저 — 30~90분 타임라인

| 실시간 | 실제로 일어나는 일 | 근거 |
|---|---|---|
| ~12–20분 `[추정]` | 배 1단계 완료 → **특대 섬 잠금 해제.** 이 게임의 유일한 진행 게이트가 여기서 끝난다 | `IslandTravel.cs:53` |
| ~25–30분 `[추정]` | 특대 섬 첫 방문. 엔진부품 24개가 거기 있다 → **경비행기 엔딩 즉시 가능** | scene:1138-1146 |
| ~35–40분 `[추정]` | 배 재료·비축 물자 전부 확보 완료. 남은 조건은 경과 15일 하나 | 아래 5장 |
| **40~74.5분** | **요구되는 행동이 "쉼터에서 E · 5분 대기" 반복 하나뿐인 34.5분** | 아래 1·6장 |
| 59.5분 | (자정 취침 사용 시) day 15 도달 — 설계 의도보다 15분 빠르다 | 아래 1장 |
| **74.5분** | day 15 도달 → 배 엔딩 성립 | `[계산]` 270 + 300×14 |
| 74.5~90분 | 없음. 게임은 이미 끝났다 | — |

## 1. 취침 루프 — 지배 전략인가? **그렇다. 비용이 정확히 0이다.**

`[실측]` `Shelter.cs:87-88` `nextDay = clock.ElapsedDays + 1; elapsedSeconds = (nextDay + 0.25f) * secondsPerDay;`
`[실측]` `SurvivalClock.cs:124` `elapsedSeconds += Time.deltaTime`(시계는 실시간과 1:1) · `SurvivalTickDriver.cs:51`
`survivalStats.Tick(Time.deltaTime, ...)` — **허기/갈증은 시계가 아니라 `Time.deltaTime`으로 감소한다.**

취침은 **시계만 순간이동시킨다.** 실시간은 1프레임도 흐르지 않는다. 따라서 —
**비용:** 실시간 0초 · 허기 0 · 갈증 0 (감소는 실시간 기준인데 실시간이 안 흘렀다).
**이득:** 체력 +15(`Shelter.cs:17`) · 일사병 →0(`:93`) · 경과 일수 +1(배 엔딩의 마지막 조건) · 밤 삭제.

**비용이 정확히 0이고 이득이 넷이다. 지배 전략 여부를 논할 것이 없다.**

### 1-1. 시계 계산
`[실측]` `secondsPerDay 600`(scene:1019) · `newGameStartTimeOfDay 0.3`(`DayNightCycle.cs:67`) → t=0에 `elapsedSeconds = 180`.
`[계산]` 첫 일몰(TimeOfDay 0.75) = (0.75 − 0.30) × 600 = **270초**.
`[계산]` 일몰 취침 루프: 일출 0.25 → 일몰 0.75 = 0.5일 = **300 실초당 1일**.
→ day D 도달 실시간 = 270 + 300(D−1). **day 15 = 270 + 4200 = 4470초 = 74.5분.**
`[계산]` 취침 안 함: 15 × 600 − 180 = 8820초 = **147.0분.**

### 1-2. `[발견]` 자정 이후 취침은 1.25일을 건너뛴다 (설계 의도 아님으로 보인다)
밤은 TimeOfDay 0.75 → 1.0(=다음 날 인덱스 0.0) → 0.25로 이어진다. **자정을 넘는 순간 `ElapsedDays`가 이미 +1 되어 있다.**
`[계산]` 자정 직후(day 인덱스 D, t=ε)에 자면 `nextDay = D+1` → `elapsed := (D+1.25)×600`. 현재 `(D+ε)×600`. **점프 = 1.25일.**
의도한 "이 밤의 아침"은 (D+0.25)이므로 점프는 0.25일이어야 한다. **1일이 공짜로 나온다.**

`[계산]` 자정 취침 루프: 일출(D, 0.25) → 자정(D+1, 0.0) = 0.75일 = 450 실초 → 취침 → (D+2, 0.25). **2일 / 450초 = 225초당 1일.**
첫 자정 = 실시간 420초. k회 취침 후 day = 2k, 실시간 = 420 + 450(k−1). **day 15 = 3570초 = 59.5분.**

→ **설계된 74.5분 페이싱이 20% 잘려나간다. 씬 값 어디에도 이 15분이 기록되지 않는다.**

### 1-3. 밤 콘텐츠는 죽는가? **첫 쉼터 이후 100% 죽는다.**
밤에만 존재하는 게임플레이를 전수 확인했다. **하나도 없다.**
- 위험요소: `HazardSource.cs:100` `Update()`는 접촉 쿨다운·재등장 타이머만 돌린다. **이동/추격/야간 각성 코드가 없다.**
- 날씨: `WeatherSystem.IsRaining`을 읽는 곳이 프로젝트 전체에 **0곳**(조명/파티클/오디오 전용). 게임플레이 영향 0.
- 모닥불: 조리 전용. `Campfire.prefab:77 secondsPerFuel 90`은 낮에도 똑같이 쓰인다.
- 남는 것은 `DayNightCycle.nightIntensity 0.10`, 즉 **어둠뿐이다.** 취침은 그 5분을 0원에 삭제한다.

## 2. 일사병 — 취침 루프가 만든 유일한 상시 압력 (그리고 아무도 모른다)

`[실측]` scene:693-695 `sunstrokeGainPerSecond 0.25` / `Recovery 0.2` / `Damage 1.0` · scene:702 `healthRegen 0.5`
`[실측]` `SurvivalStats.cs:333` `if (isInShade || !isDaytime)` 일 때만 회복. 그늘 판정 = 머리 위 20m 레이캐스트,
레이어 6(`SurvivalTickDriver.cs:74`, scene:831-834 `m_Bits: 64`).
`[실측]` **레이어 6 오브젝트는 프로젝트 전체에서 `Shelter.prefab`(:16) 하나뿐이다.** 초목·지형·바위 전부 아니다.

취침 루프를 돌면 **밤이 없다 = `!isDaytime` 회복 경로가 영구히 닫힌다.** 남는 회복 수단은 자기 쉼터 아래뿐이다.

`[계산]` 그늘 밖 일사병 100 도달: 100 ÷ 0.25 = **400초 = 6분 40초**. 이후 체력 −1.0 + 0.5 = −0.5/초 →
100 ÷ 0.5 = 200초 → **총 600초 = 10분 만에 사망.**
`[계산]` 균형 체류비: 0.25·t_밖 = 0.2·t_그늘 → t_그늘 = 1.25·t_밖 → **낮의 55.6%를 쉼터 밑에 서 있어야 한다.**
`[계산]` 일몰 취침 루프(낮 300초): 일사병 최대 **75**에서 리셋 → **절대 100에 안 닿는다.**
`[계산]` 자정 취침 루프(낮 450초): 400초에 100 돌파 → 50초 피해 −25 HP, 취침 +15 → **사이클당 −10 HP.**

**`[판단]` 이것은 우연히 잘 만들어진 유일한 중반 규칙이다: "쉼터 없는 섬에 머물 수 있는 최대 시간 = 400초(6분 40초)."**
대형 섬 한 바퀴가 `[추정]` 5~8분이므로 정확히 경계선에 걸린다. **그리고 이 규칙은 게임 안 어디에도 표시되지 않는다.**
(쉼터 키트는 반복 제작이 가능하므로, 섬마다 쉼터를 세우는 것이 정답이다. 아무도 스스로 도달하지 못한다.)

## 3. 섬 이동 시점 — 게이트가 하나뿐이고, 그것도 20분 안에 끝난다

`[실측]` scene:668 `startingItemPool[0]` = **고무보트. 시작 아이템이다.**
`[실측]` `PlayerInventory.cs:68-74 CanCarryToIsland` — 막히는 것은 **ExtraLarge 하나뿐.** 대형은 0분부터 갈 수 있다.
`[실측]` scene:1006 `stageRequiredToBypassCurrent: 1` — 특대는 배 **1단계** 완료로 열린다.
`[실측]` 이동 비용: `MinimapUI` → `IslandTravel.TryTravelTo` → `TeleportPlayerToIsland`. **즉시 텔레포트, 비용 0.**
`[실측]` scene:529-536 배 1단계 = 대나무 4 + 노끈 3 + 나뭇가지 3 — **전부 `minimumIslandSize: 0`, 시작 섬에 있다.**
`[실측]` `BoatConstructionSystem.cs:57-63` 1·2단계 도면은 대형, 3단계는 특대 · scene:1081 `largeIslandSpawnChance: 1`(확정)

`[계산]` 특대까지의 경로: 시작 섬 채집 → 대형(도면) → 시작 섬(작업대) → 특대. **이동 4회 전부 즉시.**
`[추정]` 12~20분. **30~90분 구간이 시작되기 전에 모든 섬이 열려 있다.**

> `[판단]` "30~90분 안에 대형/특대에 도달하는가"의 답은 **"그 전에 도달한다"** 이다.
> 이 게임의 진행 게이트는 **총 1개**이고 전반 20분 안에 소진된다.

## 4. 도구 내구도 — 진행을 막지 않는다 (3배 여유)

`[실측]` `Item_손도끼.asset:18 maxUses 20` · `Item_창.asset:18 15` · `Item_라이터.asset:21 5` · 칼/물통/파이어스타터 −1(무한)
`[실측]` `ResourceNode.cs:346,360` — 내구도는 **`requiresTool`인 노드에서만** 소모된다. 씬 실측 그런 엔트리는 **금속조각 하나뿐**(scene:926-930).
`[실측]` `HazardSource.cs:277` `FindBestWeapon` = **weaponDamage 최대치를 고른다.** 창 18 > 손도끼 14 > 칼 8.

`[계산]` 손도끼 소모: 금속조각 배 6개(2단계 2 + 3단계 4) 또는 경비행기 6개, `yieldPerHarvest 1` → **6회.**
전투에는 창(18)이 있는 한 **선택되지 않고**, 위험요소 조우 기대시간이 39.8분(5장)이라 전투 소모는 사실상 0.
→ **6 / 20 = 30% 사용. 막히지 않는다.**

`[계산]` 재제작: 나뭇가지 1 + 돌조각 2, Lv1(`Recipe_손도끼.asset:19-25`). 둘 다 `minimumIslandSize: 0` →
대형 섬 1회 pass에 나뭇가지 36·돌조각 27. **대형 섬에서 무한 재제작 가능.**

`[계산]` 라이터 5회 = 450초. 그러나 `Campfire.cs:141 FindAvailableFireStarter`가 **무한 파이어스타터를 우선 소모**하고,
파이어스타터는 부싯돌1+돌조각1·Lv1이며 부싯돌은 모든 섬에 있다(scene:921-925).
→ **라이터는 1일차 보조바퀴다. 크기가 정확하다. 손댈 필요 없다.**

`[판단]` 내구도는 30~90분 구간에서 **아무 것도 아니다.** 압력을 만들려면 지금의 3배(금속조각 요구 18개)여야 한다.

## 5. 위험요소 밀도 — 섬이 커질수록 **더 안전해진다** (설계 의도의 역전)

`[실측]` scene:972-988 — 6종 × `baseChance` 0.25/0.2/0.15/0.2/0.2/0.1, 배율 1/1.75/2.5/3.25
`[실측]` `HazardSpawner.cs:143-153` — **엔트리당 확률 1회 굴림.** 즉 **섬 하나에 최대 6마리**가 구조적 상한이다.
`[실측]` `IslandSizeMetrics.cs:46-49` 산포 반경 40/72/112/160

`[계산]` 기댓값 = Σ min(1, base × 배율)

| 규모 | 기대 마릿수 | 산포 면적 (πr²) | **밀도 (마리/만m²)** |
|---|---|---|---|
| 소형 | 1.10 | 5,027 | **2.19** |
| 중형 | 1.93 | 16,286 | **1.18** |
| 대형 | 2.75 | 39,408 | **0.70** |
| 특대 | 3.58 | 80,425 | **0.44** |

**마릿수는 1.75/2.5/3.25배로 오르는데 면적은 3.24/7.84/16배로 오른다. 밀도가 단조 감소한다.**
`HazardSpawner.cs:60-65`의 "큰 섬일수록 위험" 주석은 **면적을 계산에 넣지 않았다.**

`[계산]` 조우 기대시간(랜덤워크 상한): 유효 접촉 폭 `[추정]` 1.2m(플레이어 캡슐 반경 ~0.5 + 위험요소 반폭
0.08~0.45, `HazardSpawner.cs:364-414`) × `moveSpeed 5`(scene:806) = 6 m²/초.
→ 대형 39,408 ÷ 2.75 ÷ 6 = **2,388초 = 39.8분** · 특대 80,425 ÷ 3.58 ÷ 6 = **3,745초 = 62.4분**

`[계산]` 반대편(화력): 창 18 → 곰 50HP 3타 / 식인종 35 2타 / 벌떼 12 1타 / 상어 25 2타.
회복은 붕대·해독제·부목(전부 Lv1, 재료 흔함) + 자연회복 0.5/초.

> **`[판단]` 죽지도 않고 시시하지도 않다. 아예 만나지 않는다.**
> 대형 섬 한 바퀴(5~8분)에 위험요소를 만날 확률은 `[계산]` 1 − e^(−450/2388) ≈ **17%**.
> 30~90분 전 구간에 플레이어가 만나는 육상 위험요소는 `[계산]` **1~2마리**다.

## 6. 자원 고갈 — 존재하지 않는다. 섬을 옮기게 하는 것은 고갈이 아니라 희소성이다

`[실측]` `ResourceNode.cs:18,21,30` `yieldPerHarvest 1` / `maxHarvestCount 3` / `respawnSeconds 60`. **스포너는 이 셋을
덮어쓰지 않는다**(`IslandResourceSpawner.cs:365-373`은 `remainingHarvestCount`만 설정) — 코드 기본값이 곧 실동작이다.
`[실측]` scene:956-959 자원 배율 1/2/3/4 · `IslandResourceSpawner.cs:194` `count = RoundToInt(baseCount × 배율)`

`[계산]` 1회 pass 산출량 = baseCount × 배율 × 3

| 자원 | 소형 | 중형 | 대형 | 특대 | 배 총 요구 |
|---|---|---|---|---|---|
| 야자잎(칼 보너스 ×2) | 36 | 72 | **108** | 144 | 42 (노끈 14) |
| 대나무 / 나뭇가지 | 6 / 12 | 12 / 24 | **18** / 36 | 24 / 48 | 10 / 3 |
| 금속조각(대형+·손도끼) / 부력통(대형+) | — | — | **18 / 18** | 24 / 24 | 6 / 2 |
| 비상식량 / 생수(중형+) | 3 / — | 6 / 6 | 9 / 9 | 12 / 12 | 12 / 12 |
| 엔진부품 (특대) | — | — | — | 24 | (경비행기 2) |

**`[계산]` 대형 섬 하나를 한 번 훑으면 배 재료가 금속조각 3배·부력통 9배·야자잎 2.6배로 남는다.**
비상식량·생수 12개만 섬 2개가 필요하고, 대형2+특대1(도면 때문에 어차피 가야 한다)이면 30개씩 나온다 = **2.5배 초과.**
그 위에 `respawnSeconds 60`이 붙는다 → **어떤 섬도 고갈되지 않는다. 60초 기다리면 다시 찬다.**

> **`[판단]` 설계 의도(섬을 옮겨야 한다)는 강제되지 **않는다**. 강제하는 것은 `minimumIslandSize` 희소성 하나이고,
> 그 희소성은 "대형 2개 + 특대 1개 = 총 3회 방문"으로 완전히 소진된다. 그 뒤로 이동할 이유가 남지 않는다.**

`[계산]` 소비 곡선도 흑자다. 74.5분(4470초) 동안 갈증 0.08 × 4470 = 357.6 유닛.
코코넛 30/개, 소형 섬 6개/60초 사이클 → **분당 180 유닛 공급 vs 분당 4.8 소비 = 37배 흑자.**

`[발견]` **코코넛 과음 판정은 죽어 있다.** `SurvivalStats.cs:410-417`이 `amount > coconutOverdoseThreshold`로 판정하는데
`Item_코코넛.asset:21 thirstRestoreAmount: 30` < `SurvivalStats.cs:177` 기본값 `40`. **30 > 40은 영원히 거짓이다.**
씬의 SurvivalStats 블록(:684-708)에 이 키 자체가 없어 코드 기본값 40이 그대로 쓰인다. 1회 섭취량이 30 고정인 이상
"많이 마시면"이라는 규칙은 성립할 수 없다 — 값 조정이 아니라 규칙 재설계 사안이다.

## 7. 30~90분에 새로 열리는 것 — 세어보면 0개다

| 축 | 30분 이후 새로 열리는 것 | 근거 |

## 8. 가장 먼저 고쳐야 할 단 하나

### **경비행기 엔딩에 시간·비축 조건이 하나도 없다.** `EndingChecker.cs:309`

```
if (aircraftRepair != null && aircraftRepair.isRepairComplete)   // ← 조건 끝. 이게 전부다.
```

`[실측]` scene:1138-1146 경비행기 재료 = 엔진부품 2 + 금속조각 6 + 연료 3 + 노끈 4.
`[실측]` 엔진부품은 특대 전용 → 배 1단계를 반드시 거친다(브리핑 기술 그대로다).
`[계산]` **그런데 배 1단계를 끝내고 특대 섬에 처음 발을 딛는 그 순간, 그 섬에 엔진부품이 24개 있다.**
금속조각(대형 18개)·연료(대형 9개)·노끈(야자잎 108개)은 도면 때문에 들른 대형 섬에서 이미 손에 있다.
→ `[추정]` **25~30분에 게임이 끝난다.** 같은 지점에서 배 경로는 45분을 더 요구한다.

**즉 이 빌드의 실제 플레이 길이는 30분이고, 내가 위에서 계산한 30~90분 구간은 전부 선택 사항이다.**
위험요소를 늘리든 언락을 넣든, **이것을 먼저 고치지 않으면 아무도 보지 않는다.**

근거 요약: 배 = 3단계 + 도면 3장 + 비축 24개 + **경과 15일** vs 경비행기 = 재료 15개 + **조건 없음**.
`ResolveAchievableEnding`의 우선순위(배 2 / 경비행기 1)는 *동시 성립* 시의 표시 순서일 뿐, **도달 난이도를 조정하지 않는다.**

**필요한 변경(코드 — 나는 `.cs`를 못 만진다):** `EndingChecker.cs`
- 필드 추가: `public int aircraftRequiredElapsedDays = 8;`
- `:309` 조건에 `&& (survivalClock == null || survivalClock.ElapsedDays >= aircraftRequiredElapsedDays)` 추가
- **8일 근거** `[계산]`: 일몰 취침 루프 기준 270 + 300×7 = 2370초 = **39.5분.** 재료 확보 완료 추정(25~30분)보다

## 9. 내 안의 약점 (내가 먼저 쓴다)

1. **`[추정]` 값이 결론을 떠받친다.** "대형 섬 한 바퀴 5~8분", "재료 확보 완료 40분"은 내가 지어낸 숫자다.
   실측 3분이면 8장 결론(30분 게임)이 더 강해지고, 15분이면 공백 구간이 절반으로 준다. **플레이 실측이 필요하다.**
2. **위험요소 조우 39.8분은 랜덤워크 상한이다.** 실제 플레이어는 자원 노드를 향해 직진한다. 자원과 위험요소가
   같은 반경(112m)·같은 균일 분포라 상관은 0이지만, 절반(20분)으로 잡아도 결론은 바뀌지 않는다.
3. **1장은 "매 일몰마다 쉼터로 돌아온다"를 전제한다.** 다른 섬에 있으면 시계 계산이 전부 늘어나고, 그 경우
   2장의 일사병이 즉시 치명적이 된다 — 1장과 2장이 서로를 떠받치고 있어 한쪽이 틀리면 둘 다 틀린다.
4. **`ProjectSettings/`가 스테이징에 없어 레이어 6의 이름이 "Shade"인지 확인하지 못했다.** `Shelter.prefab:16
   m_Layer: 6`과 씬 `shadeLayerMask.m_Bits: 64`(=1<<6)의 일치만 확인했다.
5. **나는 이 게임을 플레이해 본 적이 없다.** 전부 파일 파싱과 산술이다.

## 10. 우선순위

이 구간에는 **막는 것도, 주는 것도 없다.** 자원 3배 잉여 · 위험요소 조우 0~2회 · 언락 0개 · 밤 없음.
남은 조건은 시계 하나이고, 그 시계는 다른 엔딩이 통째로 우회한다.

1. **경비행기에 시간 게이트** — 이걸 안 하면 아래 전부가 보이지 않는 콘텐츠다 (8장)
2. **위험요소 밀도** — 확률 구조를 마릿수 구조로 (5장). 대형 섬 목표 2.0마리/만m² = **7.9마리** (현재 2.75)
3. **자정 취침 1.25일 점프** — 설계 페이싱의 20%가 조용히 날아간다 (1-2장)
4. **일사병 400초 규칙의 가시화** — 이미 작동하는 유일한 중반 압력인데 아무도 모른다 (2장)
5. **물증류기 Lv3 그라인드 제거** — 쓸모없는 보상을 위한 물통 7회 반복 (7장)
